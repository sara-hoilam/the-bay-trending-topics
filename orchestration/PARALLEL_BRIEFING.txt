GBA Pulse — parallel multi-model architecture
=============================================

Run **Claude + Composer** in parallel, then merge to Trending News (overall).
GPT-5.5 is **not** part of this workflow.

---------------------------------------------------------------------------
1) Cursor IDE: Multitask / parallel agents (human-in-the-loop)
---------------------------------------------------------------------------
Open two Cursor agent or Composer sessions at once (**Multitask Mode**, when available). Copy-paste starters: **`orchestration/COPY_FOR_PARALLEL_AGENTS.txt`**. Give each session the same @-attachments
(prompts/gba-pulse-curator-prompt.md, references/source-links.md,
templates/gba-pulse-template.html, orchestration/fragments/trendwatch.html) but pin a different model:

  • CHAT A — Claude Sonnet 4.6  → orchestration/fragments/claude.html
  • CHAT B — Composer 2         → orchestration/fragments/composer.html

When both finish, run **CHAT D** (merger) — reads claude.html + composer.html only, **not** chatgpt.html — then:

  node scripts/merge-briefing-panels.mjs

That splices fragments into index.html between the <!-- GBA_MERGE:... -->
markers. Commit and deploy.

Why fragments first?
  Two processes writing the same file without coordination will corrupt
  the file. Fragments + one merge step is the smallest safe “parallel write”
  pattern.

---------------------------------------------------------------------------
2) Programmatic: Cursor TypeScript SDK (true parallel)
---------------------------------------------------------------------------
From a script (local machine or CI with repo checkout + CURSOR_API_KEY), call
`Agent.prompt` twice inside `Promise.all`, each with a different
`model: { id: "..." }` (Claude + Composer only). Confirm current model IDs with:

  import { Cursor } from "@cursor/sdk";
  const models = await Cursor.models.list({ apiKey: process.env.CURSOR_API_KEY });

Each prompt should instruct the agent to **write only** to e.g.
orchestration/fragments/claude.html or composer.html (full inner HTML for that panel), not
index.html. A follow-up merger step reads both fragments and writes overall.html, then
`node scripts/merge-briefing-panels.mjs` splices into index.html.

---------------------------------------------------------------------------
3) Markers and merge script (already in the repo)
---------------------------------------------------------------------------
index.html contains paired comments:

  <!-- GBA_MERGE:overall:START -->   ... Trending News (merged) ...   <!-- GBA_MERGE:overall:END -->
  <!-- GBA_MERGE:claude:START -->    ... <!-- GBA_MERGE:claude:END -->
  <!-- GBA_MERGE:composer:START -->  ... <!-- GBA_MERGE:composer:END -->
  <!-- GBA_MERGE:trendwatch:START --> ... <!-- GBA_MERGE:trendwatch:END -->

Merged by `merge-briefing-panels.mjs`:

  orchestration/fragments/overall.html
  orchestration/fragments/claude.html
  orchestration/fragments/composer.html
  orchestration/fragments/trendwatch.html

`chatgpt.html` is **not** merged (GPT panel hidden and unused).

Merge:

  node scripts/merge-briefing-panels.mjs

Optional overrides:

  node scripts/merge-briefing-panels.mjs --index=./index.html --claude=./path/to/claude.html

---------------------------------------------------------------------------
4) Deploy
---------------------------------------------------------------------------
After merge: git add index.html orchestration/fragments/*.html && commit && push;
your static host serves index.html as usual.
