GBA Pulse — parallel multi-model architecture
=============================================

Yes, you can run all three models in parallel and land updates in one HTML
file. Use one of these patterns (or combine them).

---------------------------------------------------------------------------
1) Cursor IDE: Multitask / parallel agents (human-in-the-loop)
---------------------------------------------------------------------------
Open several Cursor agent or Composer sessions at once (**Multitask Mode**, when available). Copy-paste starters: **`orchestration/COPY_FOR_PARALLEL_AGENTS.txt`**. Give each session the same @-attachments
(prompts/gba-pulse-curator-prompt.md, references/source-links.md,
templates/gba-pulse-template.html) but pin a different model:

  • Composer 2
  • Claude Sonnet 4.6
  • GPT-5.5

Each session writes its HTML to a **fragment file** under
orchestration/fragments/ (see filenames below), not directly to index.html, so
nothing collides on disk. When all three finish:

  node scripts/merge-briefing-panels.mjs

That splices fragments into index.html between the <!-- GBA_MERGE:... -->
markers. Commit and deploy.

Why fragments first?
  Three processes writing the same file without coordination will corrupt
  the file. Fragments + one merge step is the smallest safe “parallel write”
  pattern.

---------------------------------------------------------------------------
2) Programmatic: Cursor TypeScript SDK (true parallel)
---------------------------------------------------------------------------
From a script (local machine or CI with repo checkout + CURSOR_API_KEY), call
`Agent.prompt` three times inside `Promise.all`, each with a different
`model: { id: "..." }`. Confirm current model IDs with:

  import { Cursor } from "@cursor/sdk";
  const models = await Cursor.models.list({ apiKey: process.env.CURSOR_API_KEY });

Typical IDs include `composer-2`; Claude / GPT slugs depend on your account —
do not hardcode without listing first.

Each prompt should instruct the agent to **write only** to e.g.
orchestration/fragments/claude.html (full inner HTML for that panel), not
index.html. A follow-up `node scripts/merge-briefing-panels.mjs` step (or the
same script invoked after `Promise.all`) performs the splice.

SDK reference: see Cursor docs for @cursor/sdk and Agent.prompt / Agent.create.

Caveats:
  • Rate limits / queueing: three simultaneous cloud or local runs may be
    throttled; have a retry or run two parallel + one sequential if needed.
  • Local runs need a clean git tree or explicit paths so agents do not fight
    over unrelated edits.
  • Overall (Live Edition) tab is still usually a **fourth** editorial merge
    step (human or a dedicated “merger” agent that reads the three fragments).

---------------------------------------------------------------------------
3) Markers and merge script (already in the repo)
---------------------------------------------------------------------------
index.html contains paired comments:

  <!-- GBA_MERGE:claude:START -->   ... editable panel body ...   <!-- GBA_MERGE:claude:END -->
  <!-- GBA_MERGE:composer:START --> ... <!-- GBA_MERGE:composer:END -->
  <!-- GBA_MERGE:chatgpt:START -->  ... <!-- GBA_MERGE:chatgpt:END -->

Default fragment paths:

  orchestration/fragments/claude.html
  orchestration/fragments/composer.html
  orchestration/fragments/chatgpt.html

Merge:

  node scripts/merge-briefing-panels.mjs

Optional overrides:

  node scripts/merge-briefing-panels.mjs --index=./index.html --claude=./path/to/claude.html

---------------------------------------------------------------------------
4) Optional next step: “Overall” automation
---------------------------------------------------------------------------
Add <!-- GBA_MERGE:overall:START --> inside panel-overall’s <main> if you want a
fourth fragment, or run a separate merger prompt that reads the three fragments
and outputs merged Top 10, then merge-briefing-panels or a second script
applies it.

---------------------------------------------------------------------------
5) Deploy
---------------------------------------------------------------------------
After merge: git add index.html orchestration/fragments/*.html && commit && push;
your static host serves index.html as usual.
